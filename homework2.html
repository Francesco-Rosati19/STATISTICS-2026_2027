Cryptographic Primitives Analysis

1. Operational Distinctions

Concept Definition & Role in the Wallet
Generation vs. Derivation Generation creates pure randomness (entropy) for the root seed. Derivation uses deterministic algorithms (BIP-32) to calculate infinite secure child keys starting from the seed without requiring new entropy.
Public-Key Cryptography Asymmetric math (e.g., secp256k1). Allows deriving a public key from a private one (easy calculation), making the reverse calculation computationally impossible. Fundamental for signing transactions.
Hashing Deterministic one-way function (Keccak-256) that compresses variable-size data into a fixed output (256 bits). Hides the public key until funds are sent, reducing its size.
Checksum Error detection algorithm. In EIP-55, it uses the hash of the address itself to decide which hexadecimal letters to capitalize, blocking 99.98% of manual typing errors.
Encoding Changing data format purely for human or system readability (e.g., the BIP-39 word list, or Base16 string), without altering the underlying cryptographic data.

2. Historical and Temporal Context

  • 1977 - RSA: Birth of public-key cryptography, proving the feasibility of asymmetric math.
  • 2001 - SHA-2 / SHA-512: Standardized by NIST. Used for key "stretching" (PBKDF2) in BIP-39.
  • 2012 - BIP-32: Hierarchical Deterministic (HD) Wallets. A single backup file generates infinite addresses.
  • 2013 - BIP-39: UX Revolution: binary entropy is encoded into vocabulary words (mnemonics).
  • 2014 - BIP-44: Standardizes derivation paths (e.g., m/44'/60'/0'/0/0).
  • 2015 - SHA-3: Standard based on Keccak's Sponge Construction (N.B. Ethereum uses the original Keccak-256 with different padding than SHA3-256).
  • 2016 - EIP-55: Implementation of the mixed-case checksum in Ethereum.

3. Why does the pipeline require multiple algorithms?

Management & Authentication

  • BIP-39 / BIP-32: Solve the Human and Management problem. The user must be able to make a secure paper backup (uniform distribution effect and avalanche effect for uncorrelated but deterministic keys).
  • secp256k1: Solves Authentication. Normal hash functions do not allow message signing; an algebraic structure showing statistical apparent uniformity is needed to hide the private key.

Spatial Security & UX

  • Keccak-256: Solves the Space problem. Compresses heavy public keys (64 bytes) adding a strict "avalanche effect" and collision resistance to obfuscate the key until use.
  • EIP-55: Solves the UX problem. Applies checksum logic at the application level (wallet software) to discard incorrect strings, guaranteeing ~15 extra bits of entropy against accidental typos.
